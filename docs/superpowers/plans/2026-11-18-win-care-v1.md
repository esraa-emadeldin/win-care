# win-care v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build win-care v1: a Windows PC care app (tray popup + main window) that scans for junk, apps, startup items and health problems, and changes nothing until the user reviews an exact plan.

**Architecture:** A Cargo workspace. `crates/core` holds every scanner, the planner and the applier, written against small traits so it is tested on temp folders with fakes. `crates/winsys` implements those traits with Windows APIs (shell file operations, registry, WMI). `src-tauri` exposes core through Tauri commands and events, owns the tray and windows. `ui/` is a Vue 3 + TS frontend that only renders and calls commands.

**Tech Stack:** Rust stable (1.100), Tauri 2 (`tauri = "2"`, `@tauri-apps/cli@2.12`), plugins `autostart`, `opener`, `single-instance`, `updater` (all `"2"`); `windows = "0.62"`, `winreg = "0.56"`, `sysinfo = "0.40"`, `wmi = "0.18"`, `serde`, `serde_json`, `thiserror = "2"`, `tempfile` (dev). Frontend: Vue 3.5, vue-router, Vite, TypeScript, `d3-hierarchy` (treemap), Vitest, Playwright, ESLint, Prettier, simple-git-hooks.

**Spec:** `docs/superpowers/specs/2026-11-18-win-care-v1-design.md`

## Global Constraints

- Windows 11 and Windows 10 22H2, x64 only. MSVC toolchain.
- No admin actions anywhere in v1; nothing requests elevation. Files outside the user's profile are reported, never deleted.
- Scan never writes. Every change goes scan → `Plan` → Review → `apply`, and `apply` re-checks each item.
- Default action is Recycle Bin. Permanent delete only for cache categories with the setting on (default off) and for "Empty Recycle Bin". An item the Recycle Bin cannot take is skipped with `NotRecyclable`, never deleted.
- Protected: `%WINDIR%`, `Program Files`, `Program Files (x86)`, other users' profiles, Documents, Desktop, Pictures, Music, Videos. Downloads items are never pre-selected.
- Reparse points (symlinks, junctions) are never followed while scanning and never deleted through.
- No telemetry, no network except the opt-in daily update check. Settings and log live in `%APPDATA%\win-care\`.
- Settings defaults: `start_with_windows=false`, `theme="system"`, `permanent_delete_caches=false`, `low_disk_alert_pct=10`, `check_updates=false`.
- Tokens: primary `#2563EB`, accent `#06B6D4`, success `#16A34A`, warning `#F59E0B`, error `#EF4444`, surface `#FFFFFF`, surface-alt `#F3F6FF`, text `#0F172A`, text-2 `#64748B`; Segoe UI Variable; 8 px spacing; 12 px radius.
- No "Free Up RAM", no "Repair file associations", no registry deletion.
- Sizes shown are measured bytes; format with 1 decimal in KB/MB/GB (1024-based), e.g. `1.8 GB`.
- Commit messages: one line, conventional (`feat(core): …`), no trailers.

## Review Focus

1. **A junction inside a scanned folder** (e.g. `%TEMP%\x` → Documents): scan must not descend, plan must not include anything under it, apply must refuse it. Test in Task 2.
2. **The world moved between scan and apply** (file modified, replaced, or gone): item is skipped as `Changed`/`Missing`, others proceed. Test in Task 4.
3. **Bin cannot take an item** (bin disabled on that drive, or item bigger than the bin's max): marked in the plan, skipped on apply, nothing permanently deleted. Test in Task 4 (core) and the veto sink in Task 4 (winsys).
4. **Long paths (>260 chars) and non-ASCII names** in temp/caches: scanned and recycled correctly. Test in Task 3 (scan) and Task 4 (winsys recycle).
5. **Access denied on a subfolder during a scan**: the scan continues and reports a count of unreadable folders instead of failing. Test in Task 2.
